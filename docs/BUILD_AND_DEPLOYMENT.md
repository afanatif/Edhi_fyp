# Build and deployment

## 1. Toolchain

The published baseline uses Flutter 3.44.0 and Dart 3.12.0. The app's Dart constraint is `^3.12.0`; [pubspec.lock](../pubspec.lock) pins the resolved Flutter dependencies.

| Tool | Use |
| --- | --- |
| Flutter / Dart | App dependencies, analyzer, tests and builds |
| Android SDK | Android platform and packaging tools |
| JDK | Android Gradle build and Firebase emulator execution |
| Node.js 22 | Retained authentication service; local Firebase tooling |
| Git | Source checkout and revisions |

Android compilation targets Java/Kotlin 17 in the checked-in platform configuration. Use `flutter doctor -v` to inspect the selected SDK/JDK paths.

## 2. Checkout and dependencies

```bash
git clone https://github.com/afanatif/Edhi_fyp.git
cd Edhi_fyp
flutter pub get
flutter doctor -v
```

The Android Gradle wrapper is included. Local SDK paths belong in ignored `android/local.properties`, generated by the Flutter/Android tooling.

Firebase project configuration is described in [Firebase setup](FIREBASE_SETUP_GUIDE.md). Keep platform app IDs and Android package registration aligned.

## 3. Run on localhost

```bash
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8080
```

Open [http://localhost:8080](http://localhost:8080). Keep the Flutter process running while using the browser. A web-server device prints the URL; it does not require an IDE-managed browser.

For an optimized local build:

```bash
flutter run -d web-server --release --web-hostname 127.0.0.1 --web-port 8080
```

Use different browser profiles, private windows or devices for citizen, driver and HQ accounts. [launch_3_portals.bat](../launch_3_portals.bat) opens local portal windows; pass a port argument if using a different local port.

## 4. Run on Android

```bash
flutter devices
flutter run -d YOUR_ANDROID_DEVICE_ID
```

Enable the device's development connection and authorize its debugging prompt. The app uses platform location permissions when requesting current location, and the image picker opens camera/gallery actions through the platform.

For Firebase Android registration, the package name is `com.eeedhi`. The namespace in the Kotlin/Gradle source is a separate build setting.

## 5. Static analysis and Flutter checks

```bash
flutter analyze
flutter test
```

Use targeted tests while working on a module, then the relevant full checks before publishing changes. The [acceptance report](ACCEPTANCE_TESTING_REPORT.md) maps the current coverage to behavior.

## 6. Firebase authorization checks

```powershell
npm ci --prefix tools/firebase-rules
.\tools\firebase-rules\node_modules\.bin\firebase.cmd emulators:exec --only firestore,storage --project demo-edhi-pdf "node tools/firebase-rules/rules.test.mjs"
```

The command runs authorization fixtures against local emulators and a separate test project name. Emulator ports are declared in [firebase.json](../firebase.json): Firestore 8085 and Storage 9199.

On Windows, if Java cannot create its local socket in a long temporary path, assign a short process-local temporary directory:

```powershell
New-Item -ItemType Directory -Force -Path 'C:\Users\Public\edhi-emulator-tmp' | Out-Null
$env:TEMP = 'C:\Users\Public\edhi-emulator-tmp'
$env:TMP = 'C:\Users\Public\edhi-emulator-tmp'
$env:JAVA_TOOL_OPTIONS = '-Djdk.net.unixdomain.tmpdir=C:\Users\Public\edhi-emulator-tmp'
```

Then rerun the emulator command in that terminal.

## 7. Web build and Hosting

```bash
flutter build web --release
```

Output is generated under `build/web`. Firebase Hosting serves this directory and rewrites application paths to `index.html`. The checked-in headers request fresh entry-point and compiled-app files.

Deploy a reviewed build using a project-management account:

```powershell
.\tools\firebase-rules\node_modules\.bin\firebase.cmd deploy --only hosting --project eedhi-b08e1
```

Deploy rules separately when they change:

```powershell
.\tools\firebase-rules\node_modules\.bin\firebase.cmd deploy --only firestore:rules --project eedhi-b08e1
```

Deployment commands are operator actions against the named cloud project. Local building does not itself publish the site.

## 8. Android build and repository deliverable

```bash
flutter build apk --release
```

Flutter emits `build/app/outputs/flutter-apk/app-release.apk`. Copy the reviewed output to `EdhiConnect.apk` when updating the repository deliverable:

```powershell
Copy-Item -LiteralPath 'build/app/outputs/flutter-apk/app-release.apk' -Destination 'EdhiConnect.apk'
Get-FileHash -Algorithm SHA256 -LiteralPath 'EdhiConnect.apk'
```

The current Gradle release build uses the local development signing configuration. For a managed distribution build, configure the release signing key through local private properties and keep the key outside Git.

## 9. Repository contents

Commit application source, platform source, dependency lockfiles, rules, documentation and the reviewed APK. Generated build trees, local tool dependencies, database exports, signing keys, environment files and runtime logs are ignored.

The repository includes client Firebase configuration for reproducible project identity. Private deployment credentials stay in the operator's local credential store.

## 10. Release procedure

1. Review the intended source and rule changes.
2. Run the analyzer and relevant regression suites.
3. Build the affected target platforms.
4. Review the resulting portal flows.
5. Update the APK/hash when the Android source or packaging changes.
6. Update the change log and affected guides.
7. Commit and publish the reviewed revision.
8. Verify the remote commit and artifact identity.
